# 콘텐츠 레벨 관리 — level / level_order

콘텐츠가 늘어도 **기존 행의 번호는 절대 고치지 않는다**가 이 문서의 전부다.
그게 가능한 이유와, 실제로 어떻게 넣는지.

## 왜 기존 번호를 안 고쳐도 되나

앱은 두 컬럼을 **상대 순서로만** 읽는다. 연속일 필요가 없다.

| 동작 | 코드 | 결과 |
| --- | --- | --- |
| 레벨 정렬 | `levelRank()` — `1-20`의 뒷자리를 숫자로 파싱 | `1-2 < 1-10` (문자 정렬이 아님) |
| 화면 번호 | `levelLabel()` — 그 군에서 **몇 번째인지** 다시 계산 | 시트가 `1-10, 1-20, 1-30`이어도 화면은 **스텝 1-1, 1-2, 1-3** |
| 피드 순서 | `roundRobinByOrder()` — `level_order` 값을 오름차순 정렬 후 라운드로빈 | `10, 20, 30`이든 `1, 2, 3`이든 동일 |
| 진행 기록 | `clip_id` 기준 | 레벨 코드를 바꿔도 통과 기록은 그대로 |

즉 **번호는 순서를 표현하는 수단일 뿐, 사용자에게 보이지 않는다.**
그래서 10단위로 띄워 두면 사이에 9개까지 그냥 끼워 넣을 수 있다.

## 규칙 3개

1. **10단위로 쓴다.** 레벨은 `1-10, 1-20, 1-30`, 슬롯은 `10, 20, 30`.
   중간에 끼울 땐 `15`, `25`처럼 사이 숫자를 쓴다. 기존 행은 건드리지 않는다.
   (`level_order`는 정수로 읽는다 — `1.5`는 `1`이 되므로 소수점 금지.)
2. **같은 표현의 다른 영상은 같은 슬롯 번호를 준다.**
   "Man on!" 클립이 7개면 7행 모두 `level_order = 10`.
   그래야 라운드로빈이 7개를 피드 전체에 흩뿌린다. 번호를 다르게 주면 연달아 나온다.
3. **새 표현은 그 레벨의 마지막 슬롯 + 10.** 새 스텝은 그 군의 마지막 + 10.
   다음에 쓸 번호는 `npm run content`가 계산해서 알려준다.

## 시트 정렬 기능은 써도 되나

**앱 기준으로는 안전하다** — 앱은 행 순서를 읽지 않고 `level`/`level_order`만 본다.
다만 두 가지를 주의한다.

- `level`은 텍스트라 기본 정렬이면 `1-10`이 `1-2`보다 **앞에** 온다. 보기용으로 쓰면 헷갈린다.
- 원본 시트를 정렬하면 다른 사람의 화면도 바뀌고, 되돌리기가 번거롭다.

→ **정렬은 "필터 보기"(데이터 › 필터 보기 › 새 필터 보기)에서만** 한다.
   나에게만 적용되고 원본 행 순서는 그대로다.
   정렬 대신 `npm run content`의 미리보기를 보는 게 더 정확하다 —
   앱과 같은 코드로 계산하므로 실제 피드 순서가 그대로 나온다.

## 중간에 끼워 넣기 — "이 클립은 3번째 스텝에 들어가는 게 맞다"

가장 자주 생기는 상황이고, **10단위 번호를 쓰고 있으면 기존 행을 하나도 안 고친다.**

| 어디에 | 넣는 값 | 결과 |
| --- | --- | --- |
| 기존 스텝 **안**의 중간 순서 | `level = 1-30`, `level_order = 15` | 슬롯 10과 20 사이에 들어감 |
| 3번째 자리에 **새 스텝** | `level = 1-25`, `level_order = 10` | 화면에서 스텝 1-3이 되고, 기존 1-3~1-5는 1-4~1-6으로 자동으로 밀림 |

`npm run content`가 스텝마다/군마다 쓸 수 있는 번호를 계산해 알려준다.

**단, 번호가 연속이면(`1-1, 1-2, 1-3 …`) 중간에 낄 자리가 없다.**
`1-25`는 `1-3`(=1003)보다 뒤(=1025)로 정렬돼 엉뚱한 곳에 붙는다.
그래서 `--renumber`로 10단위 전환을 먼저 해야 이 방법이 성립한다.

### 진행 중인 사용자는 어떻게 되나

중간 삽입은 그 스텝을 "미클리어"로 되돌린다. 예전 해금 규칙(앞에서부터 훑다가
미클리어에서 멈춤)이라면 **그 뒤 스텝이 전부 다시 잠겼다** — 2-1을 하던 사람이
1-3으로 튕겨 돌아간다.

지금은 해금선이 "클리어한 레벨 중 가장 뒤 + 1"이다(`getUnlockedLevels`).

- 이미 열린 스텝은 콘텐츠가 늘어도 **다시 잠기지 않는다**
- 진행하던 자리를 그대로 지킨다(`getCurrentLevel`)
- 끼어든 새 스텝은 해금선 안쪽이라 **도장판**과 **되돌아가기**로 언제든 갈 수 있다
- 신규 사용자는 예전과 동일 — 첫 스텝만 열린 채 시작

즉 콘텐츠 추가로 기존 사용자가 손해 보는 일은 없다. 다만 진행 중인 사람에게
새 스텝이 자동으로 들이밀리지도 않으므로, 꼭 보게 하려면 스텝 **맨 뒤**에 넣거나
기수 사이(1차↔2차)에 넣는 편이 낫다.

## 도구

```bash
npm run content              # 점검 + 앱 화면 미리보기 + 다음에 쓸 번호
npm run content:renumber     # 10단위 재번호 계획 (시트 안 건드림)
node scripts/content-levels.mjs --renumber --apply   # 실제 시트에 반영
```

`npm run content`가 잡아 주는 것:

- `level` 형식 오류(`1_4` 같은 오타) · `level_order` 누락 · `target_phrase` 누락 → **치명**, 종료코드 1
- 같은 표현인데 슬롯이 다름 / 다른 표현이 한 슬롯을 같이 씀 / 표현 3개 미만인 스텝 → **주의**
- 레벨별 화면 라벨, 표현 목록, 실제 피드 순서, 다음에 쓸 번호

## 왜 컬럼을 쪼개지 않았나

"레벨 / 레벨코드 / 레벨세부코드"로 컬럼을 나누는 안을 검토했다. 그 3단 구조는
이미 있다 — `level`의 앞자리(군) · 뒷자리(스텝) · `level_order`(슬롯). 몇 개의
셀에 담느냐만 다르다.

| 축 | 컬럼 분리 | 한 칸 유지(현행) |
| --- | --- | --- |
| 삽입 여지 | 간격 필요 | 간격 필요 |
| 오류 가능성 | 두 칸 동기화 — 한쪽만 비는 오류가 새로 생김 | 한 칸이라 불가능 |
| 스텝 통째로 이동 | 2칸 수정 | 1칸 수정 |
| 시트 기본 정렬 | 숫자로 정렬됨 | 텍스트라 `1-10 < 1-2` |
| 이전 비용 | 코드·테스트·픽스처 전부 + 마이그레이션 | 0 |

결정적인 건 첫 줄이다. **컬럼을 나눠도 사이에 넣으려면 여전히 간격이 필요하다** —
삽입 문제를 전혀 해결하지 못한다. 유일한 실익인 "시트 정렬"은 아래 `sort_key`
파생 컬럼으로 대신한다.

간격은 10이면 충분하다(사이에 9개). 한 구간이 다 차면 `--renumber`로 재배치한다 —
번호가 화면에 안 보이니 사용자 영향이 0이라 언제든 해도 된다. 100단위는
읽기만 불편해지고 얻는 게 없다.

## sort_key — 시트를 앱 순서로 정렬하기

```bash
npm run content:sortkey                              # 미리보기
node scripts/content-levels.mjs --sortkey --apply    # 시트에 반영
```

앱이 실제로 쓰는 순서(`sortClipsByLevel`, 라운드로빈 포함)의 몇 번째인지를
그대로 써 주는 파생 컬럼이다. 이 컬럼 기준 오름차순으로 정렬하면 시트가 위에서
아래로 **사용자가 보는 순서**가 된다. 손으로 채우지 않으므로 어긋날 일이 없고,
앱은 이 컬럼을 읽지 않는다(모든 컬럼을 이름으로 읽으므로 추가해도 안전).

콘텐츠를 넣은 뒤 다시 돌려 갱신한다.

## 콘텐츠 추가 순서

1. 시트에 행 추가 → `active = TRUE`, `level`·`level_order`는 위 규칙대로
2. `npm run content` — 치명 0건인지, 피드 순서가 의도대로인지 확인
3. `npm run content:sortkey -- --apply` (선택) — 시트를 앱 순서로 정렬하고 싶을 때
4. 어드민 › **쇼츠 콘텐츠 새로고침**
